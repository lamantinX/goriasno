## Why this matters

`npm run lint` is `tsc --noEmit`, but `tsconfig.json` has no `strict`,
`noUnusedLocals`, `noUnusedParameters`, or `noImplicitAny` — so dead imports
(the `DELIVERY_AREAS` import in Hero that Plan 014 removed), unused catch
bindings, and implicit-`any` holes all pass silently. That is the root cause
that let the dead code in Plan 014 and the dead deps in Plan 015 accumulate
undetected. There is also no real linter (no eslint/biome) or formatter, so
style drift goes uncaptured. This plan tightens the typecheck to `strict` +
`noUnusedLocals` + `noUnusedParameters` (fixing the small number of surfaced
errors), excludes the plain-JS backend from typecheck, and adds Biome as a
fast, single-tool linter with a minimal config and a `npm run biome` gate —
without reformatting the whole repo (which would create a huge diff).

## Current state

### The repo

- `tsconfig.json` (entire): `target: ES2022`, `experimentalDecorators`, `useDefineForClassFields: false`, `module: ESNext`, `lib: [ES2022, DOM, DOM.Iterable]`, `skipLibCheck`, `moduleResolution: bundler`, `isolatedModules`, `moduleDetection: force`, `allowJs: true`, `jsx: react-jsx`, `paths: {"@/*": ["./*"]}`, `allowImportingTsExtensions: true`, `noEmit: true`. **No `strict`, no `noUnusedLocals`/`noUnusedParameters`, no `include`/`exclude`.**
- `package.json:11`: `"lint": "tsc --noEmit"`. No `biome`/`eslint`/`format` script. No linter devDependency.
- `server.js` is a plain Node JS file (run with `node server.js`), not part of the TS app. With `allowJs: true` and no `exclude`, `tsc` currently also typechecks `server.js` (laxly). Under `strict` + `noImplicitAny`, `server.js`'s unannotated params (`escapeHTML(str)`, `app.get('*', (req, res) => ...)`) would surface implicit-any errors. This plan EXCLUDES `server.js` from tsc (it's a standalone Node script, run with `node`, not part of the bundled TS app) rather than annotating it.

## Steps

### Step 1: Tighten tsconfig.json

Edit `tsconfig.json` to add the strict flags and an `exclude`. The final
`compilerOptions` additions (place them alongside the existing flags):

```jsonc
{
  "compilerOptions": {
    "target": "ES2022",
    "experimentalDecorators": true,
    "useDefineForClassFields": false,
    "module": "ESNext",
    "lib": ["ES2022", "DOM", "DOM.Iterable"],
    "skipLibCheck": true,
    "moduleResolution": "bundler",
    "isolatedModules": true,
    "moduleDetection": "force",
    "allowJs": true,
    "jsx": "react-jsx",
    "paths": { "@/*": ["./*"] },
    "allowImportingTsExtensions": true,
    "noEmit": true,

    "strict": true,
    "noImplicitAny": true,
    "noUnusedLocals": true,
    "noUnusedParameters": true,
    "forceConsistentCasingInFileNames": true
  },
  "exclude": ["dist", "node_modules", "server.js", "playwright-report", "build"]
}
```

(`noImplicitAny` is implied by `strict` but listed for clarity. The `exclude` removes `server.js` (plain Node JS), build output, and reports from typecheck.)

**Verify**: `npm run lint` — expect it to FAIL now with a small number of errors. Capture the full error list (`npm run lint 2>&1 | tee /tmp/lint.txt`). Proceed to Step 2.

### Step 2: Fix the surfaced tsc errors (minimal edits)

Work through the error list from Step 1. Fix each in the cited file with the
smallest change that satisfies the type system, matching existing patterns.
Predicted fixes:

- `src/App.tsx` — the `catch (e)` in the `useEffect` that loads submissions: change `} catch (e) { setSubmissions([]); }` to `} catch { setSubmissions([]); }` (optional catch binding; `e` was unused).
- Any `catch (e)` that USES `e` (e.g. `console.error(err)` in `Modal.tsx:110` / `FeedbackSection.tsx:114`) — under strict, `err` is `unknown`; `console.error(err)` accepts `unknown`, so no change needed. Only fix if tsc complains.
- If `tests/example.spec.ts` surfaces an error (e.g. an unused `page` or implicit any), fix minimally — do not weaken the test assertions (Plan 008 already fixed them).

For each error: fix → re-run `npm run lint` → confirm the error is gone and no NEW error appeared. Iterate until `npm run lint` exits 0.

**Verify**: `npm run lint` exits 0. `npm run build` exits 0 (build also typechecks via Vite's react plugin; confirm no new build error).

### Step 3: Add Biome as a devDependency + scripts

Run: `npm install --save-dev @biomejs/biome`

In `package.json` `"scripts"`, add (after `"lint"`):
```json
"biome": "biome lint .",
"format": "biome format --write .",
"format:check": "biome format ."
```

Do NOT run `format` or `format:check` in this plan (whole-repo reformat is out of scope).

**Verify**: `npm install` exits 0; `npx biome --version` prints a version. `node -e "JSON.parse(require('fs').readFileSync('package.json','utf8'))"` exits 0.

### Step 4: Create a minimal biome.json that lints without reformatting noise

Create `biome.json` in the repo root:

```json
{
  "$schema": "./node_modules/@biomejs/biome/configuration_schema.json",
  "files": {
    "ignore": ["dist", "node_modules", "playwright-report", "build", "package-lock.json"]
  },
  "formatter": {
    "enabled": false
  },
  "linter": {
    "enabled": true,
    "rules": {
      "recommended": true
    }
  },
  "javascript": {
    "globals": ["Playwright"]
  }
}
```

`formatter.enabled: false` ensures `biome lint` does NOT reformat (we only want lint signal now). `recommended` enables a sensible rule set.

**Verify**: `npx biome lint .` runs. It will likely report some warnings/errors. Proceed to Step 5.

### Step 5: Get `biome lint` to a clean-enough state

Run `npx biome lint .` and triage:

- For each `error` (not `warning`): either fix the code minimally (preferred, if it's a real issue) OR disable that specific rule in `biome.json` under `linter.rules` with a one-line comment explaining why (e.g. `"style/useImportType": "off"` if it noise-flags type-only imports). Prefer fixing over disabling.
- `warning`s may remain — Biome exits non-zero only on errors by default? Actually `biome lint` exits non-zero if there are errors OR warnings depending on `--error-on-warnings`. Default: exits non-zero on errors. To keep `npm run biome` a usable gate, aim for **0 errors** (warnings acceptable).
- If a rule produces >3 noisy hits that would require non-trivial refactoring (e.g. `useExhaustiveDependencies` flagging every `useEffect`), disable that one rule in `biome.json` with a comment, rather than rewriting effect deps in this plan.

**Verify**: `npx biome lint .` → 0 errors (warnings may print). `npm run lint` still exits 0 (tsc unaffected by Biome).

- If a future PR adds a new dependency that's imported but unused, `noUnusedLocals` will now catch the unused import at typecheck time — preventing a repeat of the `DELIVERY_AREAS`/`motion`/`@google/genai` accumulation.
